# Roadmap

Open and new work is organised by GitHub milestones ([DEC-029](DECISIONS.md#dec-029--milestones-instead-of-stages)). Every open or new issue has exactly one milestone (Backlog counts) and no `Stage N: ` title prefix or `stage:N` label. Closed issues, requirement IDs and the stage documents ([STAGE-2.md](STAGE-2.md), [STAGE-3.md](STAGE-3.md), [STAGE-5.md](STAGE-5.md)) keep their stage history; their tables remain the source for requirement IDs. The milestone on GitHub is authoritative if the table differs.

Order: M1 to M11 by number, then Backlog; the owner can pick a milestone out of order. Timers (W-CFG-04) stay excluded. M5 depends on authorized hardware. Listing and launch work (#25) waits for the owner. Closing rule ([DEC-030](DECISIONS.md#dec-030--milestone-closure-includes-a-minor-release)): a milestone closes only after at least a minor release and a README update; publication steps stay owner-gated. Merge approval: M1 and M2 have a bounded standing approval (DEC-029 item 4, DEC-022 item 4); issues that write to devices (#149, #27, #28) keep per-PR approval. Nothing is published, submitted or announced without the owner's instruction ([DEC-023](DECISIONS.md#dec-023--staged-first-public-release)).
