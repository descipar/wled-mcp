## New direct alternative: davidray/superlights

- Source: [github.com/davidray/superlights](https://github.com/davidray/superlights), default branch `main`, HEAD `35aa9e4a0e1a815dc36c483b781e936629a1ead4` (2026-10-29), created 2026-08-15, MIT (LICENSE file), no releases, 89 commits, 0 stars, one contributor. Server package `wled-lights-mcp` 0.1.0 (TypeScript, Node >= 18, MCP SDK 1.x); no npm, PyPI or registry listing found.
- Documented (README): "control WLED-based house lighting from Claude" with a self-hosted scheduler; two processes (local stdio MCP server plus an always-on HTTP trigger add-on packaged for Home Assistant); setup via `claude mcp add`; MCP prompt `setup` walks registration, calibration and schedule.
- Code observed (`mcp-server/src/index.ts`, files listed from the tree, not run): 32 tools registered: `list_devices`, `get_device_state`, `add_device`, `remove_device`, `list_effects`, `list_palettes`, `get_effect_info`, `set_power`, `set_brightness`, `set_effect`, `set_segment`, `list_presets`, `save_preset`, `apply_preset`, `delete_preset`, `set_playlist`, `set_raw_state`, `list_scenes`, `play_scene_live`, `stop_live`, `get_calibration`, `set_calibration`, `identify_leds`, `annotate_led_capture`, plus eight schedule tools (location, default schedule, holiday windows, overrides). Client uses `/json/state`, `/json/info`, `/json/eff`, `/json/pal`, `/json/fxdata`. A CI workflow runs a tool-schema check script (`check-tool-schemas.mjs`) and unit tests exist for several modules; results were not executed.
- Differentiators: scenes are rendered per physical LED position and streamed over DDP, bypassing WLED's effect engine; a photo-based LED position identification and annotation flow; a holiday/event scheduler with sunrise/sunset rules that runs in the add-on (not in WLED `timers`); gamma correction for streamed colours.
- Comparison against this project: it covers a similar basic control, preset and playlist surface, but its signature features fall in areas this project excludes by decision: DDP/realtime streaming and per-pixel colours (W-RT-01/03, W-SEG-23, SEG-06 in ISSUE-13-DEC-001), timers and schedules (W-CFG-04, ADV-02, here moved off-device into an add-on) and an unrestricted raw state tool (`set_raw_state`; ADV-01 is excluded and `raw_state_patch` stays rejected). This project's `wled_patch_raw_state` and preset snapshot/restore tools differ in scope; whether `set_raw_state` validates anything was not read. No evidence about readback, uncertain-write handling, access protection of the trigger endpoint beyond the documented `trigger_token`, or snapshots was collected. No Windows/cross-platform or test-run evidence.
- Why not adopted automatically: runtime design depends on a Home Assistant add-on for scheduling and streaming, and its main features are excluded here. Reuse permission exists (MIT) but is not authorized by this note.
