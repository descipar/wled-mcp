### Reading choices

- A room is derived from stored room-kind groups; there is no inventory field, so there is one source of
  truth and `wled_add_device` is untouched.
- `data.room_conflicts` is omitted when there is no conflict, so existing results keep their shape
  (apart from `room: null` per device and `kind` per group).
- The conflict check on save reads then saves; two processes saving two rooms at once are not
  coordinated (the same limit as every store write; listings and room actions still report the conflict).
- `dry_run` of `wled_apply_room` stays class `control` (TD-20-2), so `read-only` has no room preview; it
  can use `wled_plan_scene` and `wled_plan_zone`.

### Limits

- Mock evidence for the implementation; partial failure, unreachable member, strict versus best-effort
  across devices and conflicts between controllers are mocks only (the live run has one controller).
- Not delivered (carried): scene format 2 or room targets in scenes, a separate plan tool, room listing
  and save tools besides the group tools, a master state for a partly assigned member, scheduling.

### Common rules for all live runs

Each run needs its own explicit owner authorization naming the run, the selected test controller and the
number of calls; it is used once and expires. The target is addressed only by its inventory host name
resolved at run time; no IP, MAC or private host name is written to any file, issue or PR (DEC-005,
`scripts/check_private_identifiers.py`). A temporary inventory outside the repository (`devices = []` or the
one selected controller) carries the range in a hand-written `[discovery]` table, so no tool writes; its
hash is recorded before and after and stays unchanged. Reach: mDNS up to 3 rounds in a 6 s window plus
one read-only `GET /json/info` per announced private host, and one `GET /json/info` per host of each
configured RFC 1918 range (at most /24, at most 4 ranges) under the
[hard caps](../contract/discovery.md#hard-caps); only `tools/list` and `wled_discover_devices` are called,
single flight, stderr and logs free of addresses, MACs and ranges, a failed call recorded and not repeated
blindly. Offline checks first, built from the merged head of `main`. Run 1 is stdio on the host, run 2 HTTP
in a container (Docker Desktop, default bridge, own project and credential, deployed service untouched),
run 3 the same container evaluated against "mDNS finds nothing, unicast does"; a container that cannot
reach the range is recorded as `no reach from the container`, a network finding, not a pass.

### Known limits

One run each, one network, one Docker Desktop version class, not a matrix. A /24 unicast run sends up
to 254 read-only requests to LAN hosts (the authorization must say so). A Linux host with a bridge or
`network_mode: host` can behave differently and is not covered. The mDNS verification reaches every
announced private host, so a run limited to one device is not possible.

## Issue #235: slim served tool schemas and token budget

Evidence for [#235](https://github.com/descipar/wled-mcp/issues/235) (milestone M9, DEC-028). Scope:
shrink what `tools/list` serves without changing behavior; no tool, name, annotation, field name,
validation rule or result changed. Mocks and in-memory servers only; no device or LAN contact.

### What changed and method

`src/wled_mcp/schema_slim.py` removes the generated `title` of every schema node and `"default": null`
on nullable optional fields before serving (input schemas and the shared output schema); validation uses
the untouched pydantic models. Signal tool texts are shorter, a repeated overwrite trailer was removed from
five tools and a few scene, zone and segment texts were reworded; every safety statement stays (`dry_run`
hint, LIVE EFFECT warnings, never-replayed and uncertain statements, `overwrite`/`allow_overlap`, "omitted
means unchanged", capability evidence rules). `tests/test_tool_budget.py` enforces a per-tool and
per-profile size budget (about 3 percent above the measurements; growth needs a deliberate raise plus an
update here) and checks that served guidance resolves every tool and field it names. Not done: tool
groups (tracked separately), flattening `anyOf`, dropping non-null defaults.

Method: servers built in memory per profile and read through an MCP client; size is the character count
of compact JSON of `name`, `description` and `inputSchema` (output schema separate), about 4 characters
per token; before = `origin/main` at `29b6c54`.

## Issue #246: simplified segment schema

Evidence for [#246](https://github.com/descipar/wled-mcp/issues/246) (milestone M9, DEC-020, DEC-028).
Scope: advertise one canonical form for the optional fields of the segment models; no tool, name, result,
validation rule, bound or `required` list changed. Mocks and in-memory servers only; no device contact.

### What changed and method

- (a) `slim_schema(..., collapse_null_in=SEGMENT_MODEL_NAMES)` serves the non-null branch of every
  optional, two-branch nullable property of the `SegmentPatch` and `LayoutSegment` definitions (siblings
  such as `description` kept). It changes `wled_patch_segments`, `wled_replace_layout` and
  `wled_preview_layout` only (no other served tool embeds these models). Required fields (`id`; `start`,
  `stop` in `LayoutSegment`) and every other tool schema stay as generated. Validation uses the unchanged
  pydantic models, so explicit `null` is still accepted.
- (c) Bounded: repeated clauses in the segment field descriptions were cut ("; IDs are device-specific",
  "Omit to preserve the existing value.", "; requires field evidence" (the model description keeps "need
  fresh capability, field or matrix evidence"), "; omit to preserve an existing label"). The mutual
  exclusion (`effect_id`/`effect_name`, `palette_id`/`palette_name`) and "supply with" (`start`/`stop`,
  `start_y`/`stop_y`) statements stay; "omitted fields preserve existing values" remains in the tool
  descriptions and server instructions.
- (b) Not implemented. Each tool's schema is independent, so the single `$defs` entry cannot be shared
  across tools; inlining saves only the wrapper (about 58 characters per tool, 0.3 percent). `$ref`/`$defs`
  is already served by every released version.
- Carried follow-up, not done here: applying (a) generically in `slim_schema` to all tools would save
  about 2.5k further characters in `full` (measured on the packet's stand-in: 5376 against 2884, i.e.
  about 8 percent in total); it would also touch `wled_set_state`, `wled_save_preset`, `wled_store_preset`
  and about 20 more schemas and need more migration rows.

Method: servers built in memory per profile and read through an MCP client; size is the character count of
compact JSON of `name`, `description` and `inputSchema`; tokens are about characters / 3.5 (a heuristic;
the #235 notes used 4). Before = `origin/main` at `92e2afc`.

| --- | --- | --- | --- | --- | --- |
| `full` | 66561 | 62914 (17975) | 3647 (5.5 %, about 1042 tokens) | 2828 | 819 |

| `read-only` | 22378 | 21181 (6052) | 1197 (5.3 %, about 342 tokens) | 924 | 273 |

(a) alone is the saving of the null collapse on top of (c); (c) alone is the saving of the description edits

Client classes and `$ref`: unknown from repository evidence for all three client classes (stdio client,
hub, remote chat client); no client-side observation exists in the validation notes. Because (b) is left
out, no client dependency on `$ref` handling is added or removed.
