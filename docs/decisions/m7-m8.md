### ISSUE-183-DEC-002 — Room design defaults

- Recorded date: 2026-11-16.
- Status: active technical proposal accepted by the coordinator for issue #183 only; not a human
  decision; the owner can change any item at the merge decision (DEC-028).
- Decision:
  1. A room is a stored group with optional `kind` (`group` default, or `room`); format stays
     `wled-mcp.group` version 1, plain groups are written without `kind`, existing files are never
     rewritten; belonging derives from room-kind groups.
  2. One room per controller; a second assignment is a conflict before any save or write; plain
     groups may overlap.
  3. One new control tool `wled_apply_room(room, state | scene_id, mode, dry_run)` reusing the
     scene planners and `Resources.write_verified`; no new write primitive, application or
     verification value or error code. A state patch is refused for a room whose members designate
     segments; a scene applies only if everything it touches lies inside the room and its
     designated segments, else the whole request is refused before any write.
  4. Optional `room` on `wled_plan_zone` and `wled_apply_zone`; a segment outside is refused
     (`outside_room`).
  5. Partial failure never reports overall success; unknown outcomes are `WRITE_OUTCOME_UNKNOWN`.
  6. The served schema budget is raised as measured (docs/validation/m7-m8.md).
- Contracts: docs/contract/rooms.md, groups-scenes.md, zones.md.

### ISSUE-201-DEC-001 — Inventory writer defaults TP-201-1 to TP-201-5

- ID: ISSUE-201-DEC-001
- Status: proposed (active for the #201 implementation); coordinator technical proposal, not a human
  decision; the owner can change any item at the merge decision or later.
- Source: requirements packet for #201; contract text in
  [contract/discovery.md](../contract/discovery.md#reload-semantics).
- Scope: #201 and its users #202, #203 (M8). Not a global rule.
- Decision:
  - TP-201-1 Backup: one sibling `<config filename>.bak`, mode copied, atomically replaced by every
    successful write; backup failure is `STORAGE_FAILED` with nothing changed. `config add-device`
    and `config init --force` keep it too.
  - TP-201-2 Lock: sibling `.<config filename>.lock`, OS exclusive lock plus in-process lock, 5 s
    bounded wait; timeout is `STORAGE_FAILED` `data.reason` `locked` (CLI `CONFIG_LOCKED`); never deleted.
  - TP-201-3 `file_changed` baseline: SHA-256 of the bytes loaded at startup
    (`StartupConfig.config_sha256`), advanced by each own write; no baseline always conflicts.
  - TP-201-4 One `InventoryWriteError`: lock/permission/I/O failures are `STORAGE_FAILED`; bytes
    differing from baseline are `INVENTORY_CONFLICT`; invalid candidate, changed profile or
    `max_class`, or dropped ID are `INVENTORY_RELOAD_FAILED` before the replace; an apply failure
    restores the previous bytes (`not_applied`, or `unknown` if the restore fails).
  - TP-201-5 An unchanged candidate writes nothing and makes no backup; edits are a callback
    `edit(current: bytes) -> bytes | None`; no `[discovery]` or `devices[].mac` key added by #201.
- Conditions: M8 implementation. Refinement: the profile is compared with the loaded file, not the
  running policy (so `serve --profile` does not block writes); caps are compared with the running policy.
- Affected: DISC-09, DISC-10, DISC-T06. Supersedes / superseded by: none.

  - TP-203-6 Config: `devices[].mac` optional, normalized to lowercase 12 hex (colon form accepted on read), locator `devices[i].mac: invalid`, no startup uniqueness check, written by the tool only, passed to discovery matching.
  - TP-203-7 Write: the edit callback appends one `[[devices]]` block via `append_device` and self-checks that the parsed result equals the old document plus exactly that entry (else `INVENTORY_RELOAD_FAILED` stage `validation`, nothing written), through `Resources.inventory_writer()`; backup, atomic replace, rollback and baseline from the #201 writer. `max_class` never set.

### ISSUE-236-DEC-001 — Tool group names, membership and selection defaults

- ID: ISSUE-236-DEC-001
- Recorded date: 2026-11-26.
- Status: accepted (active for issue #236). The grouping was proposed by the requirements role within
  the issue text, which assigns the exact grouping to this issue and names `[access] tool_groups` and
  `serve --tool-groups`; the owner reviewed it and accepted it unchanged on 2026-11-26.
- Source: owner acceptance of the proposed grouping, main session, 2026-11-26 ("ok, das passt so.
  accepted"), after reviewing the seven groups, the always-on `core` and the profile intersection;
  issue #236 text (owner-authored); measurement by the requirements role, 2026-11-26, method of
  docs/validation/m7-m8.md (characters of compact JSON of name, description and input schema,
  tokens about characters / 3.5).
- Scope: issue #236 only; the tool names of milestone M9 `main` at the time of writing (41 tools).
- Decision:
  1. Seven groups and a fixed membership (every registered tool in exactly one group):
     - `core` (8): `wled_list_devices`, `wled_get_service_status`, `wled_get_state`,
       `wled_get_effects`, `wled_get_palettes`, `wled_search_effects`, `wled_set_state`,
       `wled_patch_segments`.
     - `presets` (11): `wled_list_presets`, `wled_get_preset`, `wled_activate_preset`,
       `wled_save_preset`, `wled_delete_preset`, `wled_list_snapshots`, `wled_restore_preset`,
       `wled_store_preset`, `wled_save_playlist`, `wled_export_presets`, `wled_import_presets`.
     - `scenes` (12; groups, rooms, scenes and zones): `wled_list_groups`, `wled_save_group`,
       `wled_delete_group`, `wled_list_scenes`, `wled_save_scene`, `wled_delete_scene`,
       `wled_plan_scene`, `wled_apply_scene`, `wled_list_zones`, `wled_plan_zone`,
       `wled_apply_zone`, `wled_apply_room`.
     - `layout` (2): `wled_replace_layout`, `wled_preview_layout`.
     - `signals` (3): `wled_start_signal`, `wled_get_signal_status`, `wled_cancel_signal`.
     - `diagnostics` (2): `wled_get_live_snapshot`, `wled_explain_lighting`.
     - `discovery` (3): `wled_discover_devices`, `wled_set_discovery_ranges`, `wled_add_device`.
  2. `core` is always registered: it holds the device IDs, state read, status and the tools that the
     other groups' texts refer to. A list names the additional groups; naming `core` is allowed and
     changes nothing. The reserved word `all` means every group and is the default when nothing is
     configured, so existing deployments do not change.
  3. The registered set is the intersection of the profile's classes and the selected groups,
     applied where the profile is applied today. Groups never widen a profile and never touch the
     device ceilings or the class model. Every group holds at least one `read` tool, so no profile
     removes a whole group and the result is never empty.
  4. An unknown or malformed group name stops startup with exit 2 and an actionable message that
     lists the valid names and the position, never the offending value (consistent with the
     existing configuration errors). Precedence: option, file, `all`. There is no environment
     variable (as for `--profile`). A change applies after a restart.
  5. Served instructions and tool texts (descriptions and schema text) name no tool of a group that is
     not selected; references to a tool that only a profile removes inside a selected group are the
     pre-existing behavior and stay. Cross-group references in
     descriptions are removed (the `wled_plan_zone` text no longer names `wled_replace_layout`); the
     instructions are composed from the registered set. Tool names and schema shapes stay unchanged;
     only these reworded texts differ.
  6. New tools state their group in their own pull request, like their class; a new group is a
     contract change with a migration note.
- Applicability / conditions: #236 and later tool additions; expires only by a superseding entry.
  Not a statement about per-endpoint tool sets ([#237](https://github.com/descipar/wled-mcp/issues/237)),
  which stays a design note.
- Rationale: the grouping follows the issue's example names and the measured cost (about 3170
  tokens for `core` against about 17975 for the unfiltered `full` list); `scenes` keeps the
  group, scene, zone and room tools together because they cross-reference each other and share
  stores; `discovery` isolates the inventory-writing tools so a deployment can leave them out.
- Affected: docs/contract/profiles.md, docs/TOOL-CONTRACT.md, docs/contract/cli.md,
  docs/contract/agent-guidance.md, docs/DEPLOYMENT.md, README.md, docs/validation/m7-m8.md,
  `tests/tool_contract.py`, `tests/test_tool_budget.py`.
- Supersedes / superseded by: none. DEC-020 (additive configuration key in a `0.x` minor) and
  ISSUE-20-DEC-001/-002 (classes, profiles, registration filter) apply unchanged.
